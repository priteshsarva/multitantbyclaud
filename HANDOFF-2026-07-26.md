### 2.2 Live scraper 404 handling — BUILT, NOT DEPLOYED

Supplier sites serve **soft 404s** (error page body, HTTP 200). Method B had a real bug: a missing `.item-stock-status` element fell into `else` and set `availability = 1`, so dead products were refreshed *into* stock.

Both scrapers now force `availability = 0` on four signals: nav failure, HTTP ≥ 400, error-page markup, missing product title. Nav failures no longer throw (previously the DB was never touched, leaving dead products in stock forever).

Artifacts: `liveMethodA.js`, `LiveMethodB.js`.

### 2.3 sync-feed stock filter — BUILT, NOT DEPLOYED

Adds `?stock=in|out` so the plugin can backfill in-stock products first. `COALESCE` matters: without it a NULL availability is invisible to *both* passes. Verified against real SQLite — in + out = total, no gaps or overlap.

Artifact: `sync-feed-handler.js`. **Deploy this BEFORE the plugin**, or `backfill_in` pulls everything and `backfill_out` pulls it again.

Suggested index: `CREATE INDEX idx_products_avail_id ON PRODUCTS(availability, productId);`

## 3. CRITICAL open item — read before enabling the stale sweep

The stale sweep marks products out of stock when `productLastUpdated` is older than N days. **This rests on an unverified assumption**: that the bulk scrapers (METHOD_A/METHOD_B) rewrite `productLastUpdated` on *every* pass, including for unchanged products. The *live* scraper does (`liveMethodA.js` sets `Date.now()` on every update); the bulk write path was never inspected.

If bulk scrapers only bump the timestamp when data changes, this feature will mark healthy in-stock products as sold out.

**Verify first:**

```bash
sqlite3 databases/watches.db "SELECT COUNT(*) total,
  SUM(CASE WHEN productLastUpdated > (strftime('%s','now')-259200)*1000 THEN 1 ELSE 0 END) fresh_3d
  FROM PRODUCTS;"
```

`fresh_3d` ≈ `total` → safe. A small fraction → **do not enable**; re-anchor the rule on `sppLastSynced` ("last seen by plugin") instead, which the plugin now records on every sync touch including the skip path.

The sweep ships **disabled**, has a dry-run, and aborts if a run would mark >40% of the catalogue.

## 7. Key decisions made this session

- Category identity = URL handle, not display name (rename detection depends on it).
- Deprecated categories **stop syncing** (user decision), which makes deprecation destructive — hence the empty-scrape and partial-scrape guards.
- New categories always insert **disabled** on an established source; enabled only on a source's first populate.
- Images stay as URL meta; never imported as WP attachments.
- Partial-COD engine is now **built in**, using WooBooster's exact meta keys so historical orders keep rendering. It self-disables while WooBooster is active.
- Stale sweep never deletes and never touches products lacking `_spp_managed = '1'`.

## 8. Traps

- `_spp_ts` is a **change-detector**, not a freshness clock. The fast-skip path returns early; `sppLastSynced` is the "we saw it" timestamp.
- WP-Cron only fires on traffic — low-traffic stores appear to have stalled sync.
- WP Fastest Cache is active on timeskeepers; checkout/JS changes need a cache clear before testing.
- Gateway IDs are site-specific. If prepaid selection "does nothing", the ID is wrong (`payment_method_<id>` via Inspect).
- Escaping inside `wc_enqueue_js("...")` is where the fatal came from. Prefer editing those blocks by hand and always lint after.
